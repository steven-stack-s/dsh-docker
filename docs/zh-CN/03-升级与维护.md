# 03 · 升级与维护

> [English](../en/03-upgrade-maintenance.md) | [简体中文](03-升级与维护.md)

## 1. 升级 DSH（无需重建镜像）

镜像构建时已把 dsh+pnpm 预装到 seed（`/opt/dsh-seed`），首次启动复制到 `/opt/dsh`。升级 = 容器内 npm 覆盖 `/opt/dsh`：

```bash
docker exec dsh npm install -g @deepseek-ai/dsh@<新版本>
docker restart dsh
```

### 版本号必须写全（不要用 `latest` / `next`）

npm 的 dist-tag 是发布者**手动指定**的别名，**不会自动前进**，三个 tag 可能指向三个不同的版本：

| tag | 本次核对时指向（2026-09-18） | 说明 |
|---|---|---|
| `latest` | `0.1.5-rc.2` | 稳定推荐版，**落后于 alpha** |
| `next` | `0.1.5-rc.2` | 更新的候选版 |
| `alpha` | `0.1.6-alpha.2` | 预览版（**本镜像当前锁定的就是它**） |

> ⚠️ 因此 `npm install -g @deepseek-ai/dsh@latest` **拿到的不是最新版**，更拿不到 alpha 版本。
> 升级时请一律写全版本号：`@0.1.6-alpha.2`。装完用 `docker exec dsh dsh --version` 核对。
>
> 📌 上表只是**某一时刻的快照**，dist-tag 由发布者手动指定、随时可能变动 —— 判断"现在指向谁"请以
> `docker exec dsh npm view @deepseek-ai/dsh dist-tags` 的实时输出为准。

> 💡 查当前实际指向：`docker exec dsh npm view @deepseek-ai/dsh dist-tags`。

> ⚠ **升级前先备份**（见 §5 备份）：跨大版本升级可能包含**不可回读**的数据格式变更 —— 例如
> `0.1.2-rc.1 → 0.1.5-rc.1` 会把会话数据升级到 V3，迁移后**旧版本无法再读取**这些会话（原文件保留，
> 但新版格式不被旧版识别）。因此回退 dsh 版本时必须连同 `dsh/` 数据目录一起回滚。
>
> 想留一个可回退的落点，用 `docker exec dsh rescue dsh-upgrade <版本>`：它会先把当前版本记为 last-good。

查看当前版本：

```bash
docker exec dsh dsh --version
```

> 重建镜像的场景：基础环境变化（Node 大版本 / 系统依赖），或想更新镜像内 seed 的 dsh 基础版本：
> `docker build --build-arg DSH_VERSION=<版本> --build-arg APT_MIRROR=mirrors.aliyun.com -t <你的仓库>/dsh-docker:<版本> .` 并更新 `.env` 的 `DSH_IMAGE`。

### 升级后清理残留

长期在容器内升级会累积无人回收的残留，用 `rescue clean` 清理：

```bash
docker exec dsh rescue clean            # 预览（默认 dry-run，不做任何改动）
docker exec dsh rescue clean --yes      # 确认执行
```

清理四项（全部为可证明的垃圾）：

| 项 | 内容 | 说明 |
|---|---|---|
| npm 下载缓存 | `_cacache` | 删后仅需重新下载 |
| pnpm 存储孤儿 | `pnpm store prune` | 官方语义即「只删 unreferenced」 |
| profile 虚拟存储孤儿 | `.pnpm` 中未被 `pnpm-lock.yaml` 引用的条目 | **`pnpm prune` 不会清这些**，是主要的残留来源 |
| 救援历史超限部分 | evidence / incidents | 复用既有 `RESCUE_EVIDENCE_KEEP` / `RESCUE_INCIDENT_KEEP` |

> 🔒 `--yes` 会**先自动拍一份快照**（`reason: pre-clean`）作为回退落点，并**校验它确实存在**后才开始删除。
> 若该快照创建失败、或拍完即被轮转淘汰（例如保留窗口已被占满），`clean` 会**告警并以非零退出，且不删除任何东西**
> —— 宁可不清理，也不在没有可用回退点的情况下删文件。
>
> ⚠ 为满足保留窗口（`RESCUE_KEEP`），拍 pre-clean 快照**可能**按既有轮转策略淘汰最老的**非 pinned** 快照
> （reason 以 `boot-healthy` 开头的快照会被保留，不会被淘汰）。若你手动保留的旧快照因此消失，
> 请在清理前先增大 `RESCUE_KEEP`。
>
> 除上述轮转外，清理**绝不**触碰 `package.json`、`pnpm-lock.yaml`、被引用的 `.pnpm` 条目，
> 因此不影响 `rescue rollback` 的能力。

> ⚠ 若 profile 使用默认的 `hardlink` 快照模式，被快照引用的文件 inode 仍在，
> 空间可能不会立即释放 —— 这是正常现象，待快照被轮转淘汰后回收。

## 2. 安装 / 卸载插件

```bash
docker exec dsh dsh plugin --profile web add <包名>
docker exec dsh dsh plugin --profile web remove <包名>
docker restart dsh
```

插件与数据写入 `/data/dsh` 卷，容器重建/重启不丢。

> ⚠ 插件变更（尤其 update/install）是启动失败的最高频来源。建议用《[06 · 救援模式](06-救援模式.md)》的封装命令装插件（变更前自动快照）；若装坏导致起不来，entrypoint 会自动回退。

## 3. 更换 API 密钥

```bash
# 编辑 .env，修改 DEEPSEEK_API_KEY 后：
docker compose up -d
```

## 4. 查看状态与日志

```bash
docker ps | grep dsh              # 容器状态（healthy / starting / unhealthy）
docker logs dsh --tail 100        # 日志
docker stats dsh                  # 资源占用
```

## 5. 备份

**备份整个部署目录即可**（程序 + 数据 + 配置全在里面）：

```bash
cd <部署目录>        # 含 docker-compose.yml 的目录
tar czf dsh-backup-$(date +%Y%m%d).tar.gz dsh programs workspace .env
```

恢复：把备份解压回原目录，`docker compose up -d` 即可。

> 数据中最重要的是 `dsh/`（DSH_HOME：会话、配置、插件、凭据、Hindsight 记忆库）。
> `workspace/` 是 agent 工作区，按需备份。

## 6. 更新镜像（基础环境变化时）

```bash
docker compose pull        # 拉取新版本 ghcr.io 镜像
docker compose up -d       # 重建容器
```

| 查看版本 | `docker exec dsh dsh --version` |
| 升级 DSH | `docker exec dsh npm install -g @deepseek-ai/dsh@<版本> && docker restart dsh` |
