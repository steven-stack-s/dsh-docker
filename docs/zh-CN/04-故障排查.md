# 04 · 故障排查

> [English](../en/04-troubleshooting.md) | [简体中文](04-故障排查.md)

| 现象 | 原因 | 解决 |
|---|---|---|
| 容器反复重启，日志 `listen EADDRINUSE 127.0.0.1:3080` | 旧版入口让 socat 与 dsh 抢同一端口 | 确认使用本仓库 entrypoint（socat 听 3080、dsh 听 3081），重建容器 |
| 启动报 `plugin tree failed to load` / `node:zlib` 等错误 | 基础镜像 Node 版本过低 | 使用本仓库 Dockerfile（`node:24-slim`，DSH 需 Node ≥ 22.18） |
| 页面能开但 `/api/...` 403 | 未登录（dsh-remote）或 Host 未加白（无 dsh-remote） | 装了 dsh-remote：登录，或创建首个管理员（见 [02](02-认证与远程访问.md)）。未装 dsh-remote：在 `.env` 配 `DSH_TRUSTED_HOSTS`（见 [01](01-快速开始.md)） |
| 设置页 `settings are unavailable in this browser` | DSH 设计：settings 仅 loopback | 不影响使用；改配置用宿主机 curl 调 `/api/settings.mutate`（见下文） |
| `crypto.randomUUID is not a function` | 非 HTTPS / 非 localhost 访问（浏览器安全上下文） | 用 `localhost` 访问、SSH 隧道或反向代理 HTTPS（见 [02](02-认证与远程访问.md)） |
| 首次启动从 seed 复制较慢 | Windows + WSL bind mount 跨文件系统 | Linux 部署秒级；Windows 用户可改用 docker named volume 或耐心等待首次复制 |
| `docker compose up` 报 `DEEPSEEK_API_KEY` 未设置 | 未配置 `.env` | `cp .env.example .env` 并填写密钥 |
| 容器起不来 / 反复 crashloop | 坏插件 boot 失败；自动回退未触发（无快照 / RESCUE_AUTO=off / 未装救援工具集） | 看日志是否有 `rolling back` / `lifeboat` 标记；重建镜像或用《[06 · 救援模式](06-救援模式.md)》救生舱删坏插件 |

## 在宿主机上用 curl 配置模型（设置页不可用时）

设置页不可用时，可在宿主机上用 curl 读取和修改设置。

```bash
# 1. 登录拿 cookie（已启用 dsh-remote 时；未启用则跳过）
curl -s -c /tmp/dsh-cookies.txt -X POST http://127.0.0.1:3080/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"你的用户名","password":"你的密码"}'

# 2. 查看当前设置
curl -s -b /tmp/dsh-cookies.txt -X POST http://127.0.0.1:3080/api/settings.describe \
  -H 'Content-Type: application/json' \
  -d '{"type":"client-request","rpcId":"r1","method":"settings.describe","payload":{}}'

# 3. 修改 llm-deepseek 命名空间（如 baseURL）
curl -s -b /tmp/dsh-cookies.txt -X POST http://127.0.0.1:3080/api/settings.mutate \
  -H 'Content-Type: application/json' \
  -d '{"type":"client-request","rpcId":"r2","method":"settings.mutate","payload":{"ns":"llm-deepseek","ops":[{"op":"set","path":["baseURL"],"value":"https://api.deepseek.com"}]}}'
```

## 启动失败 / 运行期崩溃：先看自动归因与事故报告

若 dsh web 起不来或运行中崩溃，容器会在 `$DSH_HOME/.rescue/` 下自动**归因并记录 incident**。请先执行：

```bash
docker logs dsh --tail 100 | grep -iE 'diagnose|heal|incident|rollback|lifeboat'   # entrypoint 归因/自愈轨迹
docker exec dsh rescue report                                                 # 事故总览（phase/根因/肇事插件/自愈 outcome）
docker exec dsh rescue report <id>                                            # 展开单条：rationale + 自愈动作 + redline 断言
docker exec dsh rescue incident list
tail -30 /data/dsh/.rescue/log/rescue.log                                     # 审计日志（卷内，离线可查）
```

> 红线说明：自动排查只读证据 + 只动插件树四件套与 `.rescue` 状态；若报告显示 `redline.cordisPatchTouched=true`（不应发生）或仍无法恢复，用 `RESCUE=1` 进救生舱手动处置（见 06-救援模式）。

**判断口径**：`report-only` = 自动归因认为非插件/缺基线，未自动改，需人工；`recovered-remove`/`recovered-rollback` = 已自动摘插件或回快照后恢复。若 incident 显示 `rootCause.category=unknown` 且始终 report-only，多为非插件问题（主程序/升级/资源），到 03-升级与维护 查 dsh-reinstall 兜底。

## 诊断信息收集


反馈问题时，请附上：

```bash
docker ps | grep dsh
docker logs dsh --tail 50
docker exec dsh dsh --version
```
