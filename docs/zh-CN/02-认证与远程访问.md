# 02 · 认证与远程访问

> [English](../en/02-authentication-remote-access.md) | [简体中文](02-认证与远程访问.md)

默认配置为**内网直连**（不装认证插件）：`3080` 端口映射到宿主机，仅局域网内可访问。
如果你需要**跨网络远程访问**（公网、异地），请按本指南加装认证并配合反向代理。

## 访问方式总览

| 方式 | 安全性 | 适用场景 |
|---|---|---|
| 本机访问（`127.0.0.1:3080`） | 最高 | 部署在同一台机器的浏览器 |
| 内网直连（`http://<内网IP>:3080`） | 高（无认证，依赖内网隔离） | 局域网内使用 |
| SSH 隧道 | 高（加密） | 单人在外临时访问 |
| 反向代理 + dsh-remote 认证 | 高（认证层 + HTTPS） | 长期远程访问 |

> 浏览器限制：`dsh web` 的部分功能（如 `crypto.randomUUID`、settings）要求**安全上下文**
> （HTTPS 或 localhost）。内网通过 IP 直连时若遇到相关报错，属浏览器安全策略，
> 可用 `localhost` 访问、SSH 隧道或反向代理 HTTPS 解决。

## 加装 dsh-remote 认证（可选，推荐远程访问时启用）

[dsh-remote](https://github.com/xgone/dsh-remote) 插件提供**账号密码 + MFA（TOTP）**认证，
登录通过后才放行 `/api`、WebSocket 与特权方法。

```bash
# 安装插件（插件与账号数据写入 /data/dsh 卷，容器重建不丢）
docker exec dsh dsh plugin --profile web add @xgone/dsh-remote
docker restart dsh
```

### 创建首个管理员

dsh-remote 的账号存于 `$DSH_HOME/auth/store.json`。账号库为空时，登录页会进入**引导模式**（"创建首个管理员账号"），默认创建为 **admin** 角色。有两种创建方式：

**方式 A —— 本机浏览器（仅 loopback）。** 在**宿主机**（或通过 SSH 隧道/本机 localhost）打开 `http://127.0.0.1:3080`，登录页会显示创建账号表单——输入用户名和密码（≥6 位）创建即可。该端点拒绝非 loopback 请求（403），防远程抢注。

**方式 B —— 配置式 bootstrap（headless / NAS / 无本地浏览器）。** 启动前在插件配置里声明凭据，dsh-remote 会在启动时预置首个管理员（幂等——账号库非空即忽略）。编辑 `profiles/web/cordis.patch.yml` 中的 `remote` 行（位于挂载的 `/data/dsh` 卷内，重启不丢）：

```yaml
- id: remote
  config:
    enabled: true
    bootstrap:             # 仅当账号库为空时使用
      username: admin
      password: '一个强密码'
```

然后重启。日志会打印 `bootstrapped first admin account ... from config`。**首次登录后请从 `cordis.patch.yml` 移除明文凭据。**

> 注意：dsh 核心本身不需要"首个管理员"，见 [01](01-快速开始.md)。本节的账号仅属于 dsh-remote。

### 登录并开启 MFA

- 访问 `http://<主机>:3080`，用刚创建的账号登录
- 设置 → 登录与账号 → 双重验证（MFA）→ 用 Google Authenticator / 1Password 扫码
- **MFA 必开**：若通过反向代理暴露到公网，认证层是唯一防线

## SSH 隧道（单人在外临时访问）

```bash
# 本地端口转发：把远程 3080 映射到本机 3080
ssh -L 3080:127.0.0.1:3080 你的账号@主机IP
# 然后浏览器打开 http://127.0.0.1:3080
```

适合 Windows/Mac/Linux 自带 ssh 的场景，无需额外配置。

## 反向代理 + HTTPS（长期远程访问，推荐）

> ⚠ **必须把域名加进 `DSH_TRUSTED_HOSTS`**：dsh 只信任 loopback 或白名单里的 Host。用域名访问却没加白时，
> 页面能打开、但 `/api` 会被 403 拒绝（表现为"界面空白 / 连接异常"）。在 `.env` 里写：
> `DSH_TRUSTED_HOSTS=app.example.com`（多个用逗号分隔，可带端口）。

以 Caddy（自动 HTTPS）为例，Nginx 同理：

```bash
# Caddyfile（域名需解析到主机；80/443 端口开放）
你的域名.com {
    reverse_proxy 127.0.0.1:3080
}
```

```bash
# 以 Docker 运行 Caddy
docker run -d --name caddy \
  -p 80:80 -p 443:443 \
  -v /path/to/Caddyfile:/etc/caddy/Caddyfile \
  -v caddy_data:/data \
  caddy:2
```

> 反代前务必确认已加装 dsh-remote 并开启 MFA（见第 2 节）。

## 安全清单

- [ ] 远程访问时：强密码 + **MFA（TOTP）**
- [ ] 不要把 `3080` 直接映射到公网（未加认证时）
- [ ] 第三方插件有完整权限，安装前查看源码
- [ ] 定期备份（见 [03](03-升级与维护.md)）
